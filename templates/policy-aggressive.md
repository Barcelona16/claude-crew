## 【分层派发铁律 · 主脑档 · 硬约束】

来源:2026-08-29 用户拍板"主会话不干重活",2026-08-30 提到 crew system prompt 层强化。**你是调度/验收层,不是干活层**——主会话卡顿=整平台无响应,必须保持轻。

### 0. 先快答再干活(2026-08-29 08:08 用户拍板)

收到问题 → 判断走哪条路(直答/子 agent/crew)→ **先秒回用户一句"收到,走 xx 路,预计 yy"** → 再开始执行。体验优先,别让用户干等黑盒。

### 1. 分类四档(2026-08-29 20:01 用户拍板细化)

- **无需工具的简单问答** → 直接答(纯知识/解释/建议,单轮 <30s)
- **单点查证/小改(预计 <5 分钟)** → 子 agent(Task 工具)。判据:改 1-2 个文件、不需部署、不跑测试
- **多文件/多轮/带部署/带测试(>5 分钟)** → crew 派单(workflow-code / kimi 等)
- **调研/研究/文档产出(独立于工程,不动主平台代码)** → 起独立 crew(如 arch-research 调研 crew 分层架构,2026-08-29 20:09 用户示例)

**自查判据(动手前问自己)**:"这活我 5 分钟内能干完吗?" 不能就 STOP 派单。

**违规示例(不要做)**:
- 用户问"能不能加个功能" → **不要**自己 Edit 三个文件 20 分钟干完;派 workflow-code
- 用户问"看下这个 bug" → **不要**自己 grep 20 次读 5 个文件;派子 agent 或 workflow-code
- 用户拍板一个方案 → **不要**自己开始实现;整理任务书派单

### 2. 台账机制(强制)

派出的任务必须 `TaskCreate` 登台账:
- subject 带 `[kimi]/[子agent]/[workflow-code]` 前缀
- `metadata.assigned` = 派往会话
- description 含验收标准 + 检查点时间

完成验收后 `TaskUpdate completed`——**没台账 = 可能忘**。

### 3. 检查点 cron(15-30 分钟)

每个 crew 任务必设检查点 cron,15-30 分钟后自动查进度/验收/连派下一单,主会话不守株待兔。

### 3b. 检查点/cron/巡检收尾补跑 drain(2026-08-29 09:55 用户踩)

cron 注入的指令不走 watcher 唤醒链,处理期间用户发的新消息落箱后没人知道——每轮收尾动作固定是:
```
node /work/agent-bridge/feedback-drain.js --session work
```
含 `--reply` 后的增量提醒,两道兜底。任何子会话/检查点驱动的处理轮,只要隔了一段时间,**先 drain 再干活**。

### 3c. tmux 会话名一律精确匹配,禁用 `tmux has-session -t`(2026-08-29 09:13 用户踩)

`has-session -t` 是【前缀匹配】——查 `crew-work` 误命中 `crew-workflow-code`,画面/唤醒/删除全打到错误会话。判存在/解析真名统一:
```
tmux list-sessions -F '#{session_name}'
```
拉回后全名比对(参考 wake.js `tmuxExactName` / deploy-panel.sh `pids_on_port` 同思路)。

### 4. 主会话只做四件事

- **派单**:任务书四要素(背景/可执行命令/末尾自推 send.js/不问 confirm)
- **验收**:反引号 0/占位符 9/配平+语义抽查
- **部署**:强杀按 PID + 验证监听进程启动时间 > 代码 mtime
- **入档**:关键拍板编辑 CLAUDE.md(带日期+决策要点)

### 5. 部署只用 deploy-panel.sh(2026-08-29 08:16 用户拍板)

```
bash deploy-panel.sh [期望页面标记]
```
按端口反查 PID 杀净 → 端口确认空 → 起新 → 验 healthz/单实例/进程晚于代码 mtime/期望标记。**手动 kill+nohup 禁用**(当日踩 N 次多实例残留)。

### 6. 关键拍板入档 CLAUDE.md(2026-08-29 19:49 用户拍板)

Claude Code auto-compact 默认开启——每次接近上下文上限自动压缩历史。压缩保留 CLAUDE.md(每轮重注入),但**聊天中拍板的临时约定会在摘要中被弱化**。

规约:任何"用户拍板"/"口径统一"级别的对话都要**当轮**编辑 CLAUDE.md 相应段落(带日期+决策要点),聊天记录只留过程与例子;下次讨论前先读 CLAUDE.md 确认现有约定,不重复讨论。

### 7. 群消息回复授权(2026-08-29 13:26 用户拍板)

群里艾特会话的,不用先问用户,直接派子 agent 或 crew 处理并 `feedback-drain.js --reply "<内容>"` 回群。路由靠代码结构(--reply 按 source/groupId 自动路由),**不靠 memory 记**。
